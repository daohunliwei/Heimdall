## 问题 10（致命）：RAG 流水线缺失 — LLM 从未拿到文件内容

**严重程度**: 致命（Wiki 内容是幻觉）

### 现象
生成的 Wiki 页面内容与真实代码完全不符。LLM 只看到文件路径列表，从未看到文件内容。

### 根因对比

| 步骤 | deepwiki-open | Heimdall（修复前） |
|------|--------------|-------------------|
| **克隆后** | `prepare_database()` → 读文件 → 分块 → 嵌入 → 存 FAISS 索引 | 仅克隆，未嵌入 |
| **页面生成前** | `RAG.call(query)` → FAISS 相似搜索 → 返回相关代码块 | **未调用 RAG** |
| **提示词构建** | `<START_OF_CONTEXT>` + 实际文件内容 + `<END_OF_CONTEXT>` | 仅文件路径链接（URL），LLM 无法访问 |
| **提示词声称** | 提供真实代码 | "You have access to the full content of these files through the RAG system" — **这是谎言** |

### 修复（本轮）

1. **`ReadPageFiles()` 新增** — 从已克隆仓库直接读取 `page.FilePaths` 中列出的文件内容（每文件上限 12KB）
2. **`BuildWikiPagePrompt()` 重构** — 接受 `fileContents` 参数，将真实文件内容嵌入提示词 `[RELEVANT_SOURCE_FILES]` 区域
3. **嵌入流水线后台启动** — 克隆完成后异步启动 `EmbedRepoAsync()`，为后续 RAG 聊天做准备
4. **提示词不再说谎** — "Based ONLY on the actual source file contents provided above"

### 待实现（Agent Loop）

当前：单次 LLM 调用生成一个页面（含文件内容）。

deepwiki-open 的 "Deep Research" 模式支持最多 5 轮迭代（逐步升级的 system prompt）。

建议后续实现：
1. **页级迭代**：首轮生成 → 审查覆盖度 → 检索更多文件 → 补充生成
2. **RAG 增强**：嵌入完成后，页面生成同时使用直接文件读取 + FAISS 语义检索
3. **质量门禁**：检查生成内容是否引用了实际代码符号，不通过则重试
