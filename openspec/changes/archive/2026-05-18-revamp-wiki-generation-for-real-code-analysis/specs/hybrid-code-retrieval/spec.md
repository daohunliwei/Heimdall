## ADDED Requirements

### Requirement: 双路混合检索
系统 SHALL 在 Wiki 页面生成阶段，对每个页面主题执行 BM25 + 向量搜索的双路检索，从代码索引中获取最相关的真实代码片段。检索结果 SHALL 包含文件路径、行号范围和相关性评分。

#### Scenario: 按页面主题检索代码
- **WHEN** 生成"用户认证模块"页面
- **THEN** 系统同时执行 BM25 搜索（关键词：认证、Auth、Login、JWT）和向量搜索（语义：用户认证流程），合并去重后返回 Top-20 代码片段

#### Scenario: BM25 和向量搜索结果互补
- **WHEN** BM25 命中精确类名但向量搜索命中相关辅助函数
- **THEN** 系统合并两路结果，去重排序后确保两者都出现在最终检索结果中

#### Scenario: 检索结果带元数据
- **WHEN** 代码片段被检索返回
- **THEN** 每条结果包含：文件路径、起止行号、编程语言、片段内容、与查询的相关性分数

### Requirement: 检索结果注入提示词
系统 SHALL 将检索到的代码片段格式化后注入 Wiki 页面生成的提示词中，取代旧的"摘要链"输入。注入的代码片段 SHALL 保持原始内容不经过摘要压缩。

#### Scenario: 真实代码注入页面生成
- **WHEN** 生成"数据访问层"Wiki 页面
- **THEN** 提示词中包含该模块相关的真实 Repository 类代码片段（完整的方法签名和实现），而非代码摘要

#### Scenario: 代码片段超出上下文限制
- **WHEN** 检索到的代码片段总长度超过页面生成的上下文预算（默认 20K tokens）
- **THEN** 系统按相关性排序，截取 Top-N 片段直至不超出预算，并在提示词中标注"已截断"

### Requirement: 搜索结果缓存
系统 SHALL 缓存同一次 Wiki 生成任务中的检索结果，避免对同一主题重复检索。

#### Scenario: 检索结果内部缓存
- **WHEN** 同一任务内多个页面涉及同一关键词
- **THEN** 第二次及以后的搜索使用缓存结果，不重复计算 BM25 和向量搜索
